# Unreleased v5: deprecated and soft-retired API migration

This is an intentional **major-version source and binary break**, not a 4.x
change. Recompile consumers after applying the replacements below. Package
versions, target frameworks, persisted MSAL v3/ADAL cache formats, OAuth
parameters, and surviving enum/telemetry numeric identifiers are unchanged.

## Scope and evidence

The audit starts at `build/template-pack-and-sign-all-nugets.yaml`, not just the
core public API baseline. It includes Core, Broker, Desktop, Desktop.WinUI3
(which compiles linked Desktop sources), Extensions.Msal, KeyAttestation, and
the release-packaged, test-infrastructure-only Microsoft.Identity.Lab.Api.
Both base and head were built and packed for every default non-mobile shipping
TFM; Android/iOS builds were attempted separately. The comparison base is
`643e17db7ca97af02a19d379136fb9339baa86e7`
on `rel/v5`.

The inventory below includes public **and protected** members, accessors,
constructors, constants, and members of obsolete types. Evidence includes
`[Obsolete]` without a message, warning/error attributes, conditional
attributes, explicit soft-deprecation, and XML documentation saying an error
is no longer raised. An attribute on a type accounts for its contained
surface. Removing an empty extension class whose only member was deprecated
also removes its namespace when it had no other types.

### Important migration behavior

* **Request authorities:** use `WithTenantId(tenantId)` or
  `WithTenantIdFromAuthority(new Uri(authority))` on request builders.
  These preserve the application's configured cloud; configure any cloud
  change with the application's `WithAuthority` before building it.
  The WAM samples use the tenant override for MSA passthrough. Select a
  public-cloud application authority when exercising public-cloud MSA SSO.
* **Clearing a user cache:** enumerate `app.GetAccountsAsync()` and await
  `app.RemoveAsync(account)` for each account instead of
  `MsalCacheHelper.Clear()`. Registered cache persistence is updated through
  MSAL while retaining its cache metadata. The CacheExtension loop uses
  this supported account-removal path before starting its shared-cache test.
* **Extra body parameters:** ordinary
  `request.WithExtraBodyParameters(dictionary)` and `null` calls now bind to
  `AbstractConfidentialClientAcquireTokenParameterBuilderExtension.WithExtraBodyParameters<T>`.
  The deleted client-specific method only forwarded to this same generic
  implementation. Explicit static calls must change their declaring class.
  HTTP body values, callback invocation, token lookup, and cache partitioning
  remain the generic implementation's behavior.
* **Extra query parameters:** use
  `IDictionary<string, (string Value, bool IncludeInCacheKey)>`. Parse legacy
  query strings into that dictionary. `false` preserves the old exclusion
  from the cache key; use `true` for values that change token identity.
  A null argument is no longer ambiguous with the removed string/dictionary
  overloads.
* **Confidential interface redeclarations:** only the obsolete `new`
  declarations are removed. `IClientApplicationBase.GetAccountsAsync()` and
  `AcquireTokenSilent(scopes, loginHint)` remain inherited and callable after
  recompilation. Prefer `GetAccountAsync(identifier)` and the account-based
  silent overload for web-app cache design. This is still a binary break for
  callers compiled against the removed redeclarations.
* **Broker:** the error-obsolete desktop `WithBroker(bool)` throwing stub is
  removed, **not** the independent Android/iOS implementation. Active
  `WithBroker(BrokerOptions)` extensions are preserved. Mobile-only obsolete
  `IsBrokerAvailable()` probes are removed; desktop declarations without
  retirement evidence remain. Desktop `WithWindowsBrokerOptions` is removed;
  its non-obsolete mobile declaration and the `WindowsBrokerOptions` type
  remain, even though Windows-only options throw on mobile.
* **Client claims:** configure `WithCertificate`, then call
  `WithExtraClientAssertionClaims(json)` on each request. These claims
  intentionally participate in the cache key. Set concrete request options
  such as `WithSendX5C` before the extra-claims extension, whose supported
  return type is an abstract builder. There is no one-to-one
  `mergeWithDefaultClaims: false` replacement; create and sign a complete
  assertion using the supported callback instead.
* **MSAL v2 cache data:** migrate it using MSAL.NET 4.x before upgrading:
  deserialize with `DeserializeMsalV2`, serialize with `SerializeMsalV3`,
  then use v3 in v5. Do not feed v2 bytes to `DeserializeMsalV3`. The
  CacheCompat v3 harness now rejects requests for v2 storage explicitly.
  Its success matrix retains the three v3 interoperability cases; separate
  offline tests verify that v2-only and mixed v2/v3 requests are rejected
  before sign-in, without requiring lab credentials.
* **WWW-Authenticate:** use the response/header APIs with an explicit scheme,
  or their multi-scheme overloads. There is no public replacement for the
  permissive, raw parameter-string parser; use real HTTP response headers.
  Scopes/resources are caller policy, not values to trust from a challenge;
  validated raw fields remain available through the indexer.
* **Region identifiers:** removed values 1, 2, 3 are not reused.
  `RegionOutcome.UserProvided` remains 6 and
  `ManagedIdentitySource.MachineLearning` remains 7 after deleting the
  obsolete `DefaultToImds` value.

  and all 14 managed assets in the package table, including WinUI3. No

  property and enum backing records. There are no unexplained differences,

* **Additional builds:** the net8 integration project, net48 MSALv3
  CacheCompat project, classic DesktopTestApp, NetFxConsoleApp, and both
  net8.0/net48 unit-test targets built successfully. Integration, interoperability,
  and interactive applications were **built, not executed**.
* **Representative consumers:** the same supported consumer compiled with
  zero warnings/errors against both BASE and HEAD packages on net8.0 and
  net48, and all four binding-check executions passed. Recompilation changes
  the two removed confidential-interface redeclarations to inherited
  `IClientApplicationBase` members and the body-parameter call to the existing
